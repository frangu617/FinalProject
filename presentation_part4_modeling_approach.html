A little professor tip

The baseline gives learning a meaningful reference. Class weighting changes the influence of existing examples; it does not create new rare hands.

Speaker notes · About 30 seconds

We compare three candidates. The majority baseline always predicts the most common training category, high card. It tells us what we gain from learning. A decision tree learns a sequence of questions, while a random forest combines predictions from two hundred trees. Both learned models use class weights to give uncommon categories more influence. Those weights do not create additional examples.

Speaker notes · About 30 seconds

To compare them fairly, all candidates receive the same training and validation hands, with the same suit and rank encoding. The encoder is fitted using training data only. We use a fixed seed so the split can be reproduced. We also compare training and validation accuracy to look for overfitting, and inspect the confusion matrix to see which categories the model confuses.

A little professor tip

Giving each category equal weight does not make a score based on one example reliable. Fix model settings before final testing, and keep test results out of selection.

Speaker notes · About 30 seconds

Our main selection score is macro F1. It balances precision and recall within each category, then averages those scores equally across categories. We report accuracy and per-category results alongside it, including the number of examples supporting each score. Once settings are fixed, the selected model is refitted on all development hands and evaluated on the separate test file. We keep those final results out of model selection.

Sources and presentation notes

Implementation and initial validation outputs: the training notebook. Candidate settings are a majority-class baseline, a decision tree with maximum depth 12 and balanced class weights, and a 200-tree random forest with weights balanced within each bootstrap sample. All use one-hot category encoding; the original positional card inputs are retained.

The notebook compares one reproducible stratified split and selects the highest validation macro F1 across all ten labels. Undefined class-level scores are displayed as zero. Very small class counts make that comparison uncertain; these initial settings and one split do not establish an optimal model.

Optional final evaluation refits the selected pipeline and reports both the full supplied test file and test records whose unordered hand was absent from development. Earlier descriptive summaries included both files. Final test results should stay out of model selection.

Method references: scikit-learn guidance on data leakage, random forest classifier, and classification metrics and support. Measured model results belong in Part 5.
